## Required Changes

### CR-003

- Priority: Major
- Status: Reopened
- 対象箇所: `1. 概要`、`2. 解決したい課題`、`3. 目的`、`6. v1のスコープと責任境界`、`7. 判断原則`
- 問題: 「重複通知」が中心課題・価値・v1範囲として使われているが、同一イベントが複数接続から届く通知を指すのか、同一監視対象に関する別イベントまで含むのかが明確でない。
- 根拠: コンセプト本文。10〜11行目、23行目、32行目、87行目、119〜121行目で「通知」「監視対象」「重複通知」が使われているが、相互の意味範囲が一意に定義されていない。
- 影響: 重複抑制の対象範囲が分かれ、提供価値およびMVPの解釈を過大または過小にする可能性がある。
- 修正内容: 「重複通知」と「監視対象」「通知」の関係をコンセプトレベルで定義し、課題・価値・v1範囲で同じ意味に統一する。重複検出方式やデータ構造は要件定義以降へ委譲する。
- 修正完了条件: 課題・目的・v1スコープ・判断原則を通読したとき、「重複通知」が何を指すか一通りに理解できること。
