## Required Changes

### CR-001

- Priority: Major
- Status: Open
- 対象箇所: `9. 前提条件と主なリスク`、`11. 未決定事項`、`12. 要件定義への引継ぎ`
- 問題: 11章でコンセプトとしての未決定事項がないと記載する一方、12章では保証境界、初期状態、遅延判定、異常情報および監視操作などを要件定義へ引き継いでいる。
- 根拠: コンセプト本文。決定済み方針、未確認の外部前提、要件定義で具体化する事項の分類が章間で明確に対応していない。
- 影響: コンセプトで確定した価値・責任境界と、要件定義で具体化する事項の境界を誤解する可能性がある。
- 修正内容: 決定済み方針、要件定義で具体化する事項、外部前提・保証対象外の区分を、9章・11章・12章で一貫させる。
- 修正完了条件: 6章・7章・9章・11章・12章を通読して、各事項の判断段階を一意に説明できること。

### CR-014

- Priority: Major
- Status: New
- 対象箇所: `1. 概要`、`6. v1のスコープと責任境界`、`9. 前提条件と主なリスク`
- 問題: ProviderがGateway接続候補を提供する記述と、利用者が到達可能な接続候補を準備する記述が併存しており、Provider・利用者・Event Streamの候補準備における役割分担が一意に読めない。
- 根拠: コンセプト本文。1章ではProviderが候補を提供するとし、6章・9章では利用者が候補を準備すると記載している。
- 影響: 主要利用場面、外部責任およびv1の成立条件について、利用者が何を準備し、Event Streamが何を利用するのかを誤解する可能性がある。
- 修正内容: 候補の取得・選択・準備に関するProvider、利用者、Event Streamの役割を、APIやデータ形式を決めずにコンセプト上で区分する。
- 修正完了条件: Providerが担うこと、利用者が担うこと、Event Streamが前提として受け取ることを、1章・6章・9章で矛盾なく説明できること。

### CR-015

- Priority: Major
- Status: New
- 対象箇所: `3. 目的`、`4. 対象ユーザーと主要利用場面`、`5. 提供価値`、`6. v1のスコープと責任境界`、`8. 成功条件`、`11. 未決定事項`
- 問題: Event Streamが監視を継続すること、運用者が接続状態を把握して継続・停止を判断すること、候補不足・全接続不健全時に異常を把握することの関係が一意に読めない。運用者が主対象ユーザーとして得る価値との対応も弱い。
- 根拠: コンセプト本文。3章・6章・8章で監視継続を示す一方、4章・5章・8章では運用者が継続・停止を判断するとしている。6章では候補不足を異常として扱いながら、残った健全な接続で監視を維持するとしている。
- 影響: Event Streamが担う価値、運用者が担う判断、正常・部分障害・全障害時に利用者が得る状態、およびMVPの境界を誤解する可能性がある。
- 修正内容: Event Streamが提供する監視状態、運用者が行う判断、監視を継続できる場合と異常を把握して停止・復旧判断を要する場合を、コンセプトレベルで区分する。詳細な状態遷移や方式は要件定義へ委譲する。
- 修正完了条件: 主対象ユーザーごとの価値と、正常時・候補不足時・全接続不健全時の期待状態を、3章・4章・5章・6章・8章で矛盾なく説明できること。
