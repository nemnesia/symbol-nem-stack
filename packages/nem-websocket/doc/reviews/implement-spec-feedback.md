## SEC-001: STOMP受信フレームサイズ上限の規範化

- 分類: SECURITY
- 該当箇所: 記載なし
- 確認できた事実: `@stomp/stompjs` 7.3.0 の受信Parserは、WebSocketメッセージをまたぐ未完成フレームを内部配列へ保持し、公開されたフレームサイズ上限を持たない。承認済みWebSocket仕様書は存在しない。
- 未決定または矛盾: 最大フレームサイズ、`content-length` の許容形式、サイズ超過・不正フレーム時のWebSocket close codeが未定義である。
- 実装への影響: 上限がない場合、悪意あるノードからプロセスのメモリ使用量を継続的に増加させられる。上限値を変更すると、受信可能なイベントの外部挙動が変わる。
- 仕様書作成者に求める決定: STOMPフレーム全体（command、headers、body、終端）の最大バイト数、`content-length` の文法・範囲、違反時に接続を破棄することを仕様へ追加すること。
- 推奨案: 最大4 MiB、非負の安全な十進整数のみを許可し、違反時はWebSocket close code 1009で接続を破棄する。
- 暫定対応: `src/stompFrameSizeGuard.ts` とWebSocket adapterで4 MiBを適用し、Nodeの`ws`には同値の`maxPayload`を指定した。仕様確定時は定数、close code、異常系テストを見直す。
- 検証条件: 分割チャンクでの巨大・負値・不正値の`content-length`、NULL終端なしの累積、上限直前の正常フレームを仕様の受け入れ条件と照合する。

## SEC-002: 再接続バックオフと試行回数リセット条件

- 分類: SECURITY
- 該当箇所: `NemWebSocketOptions` の再接続定義（既存READMEのみ）
- 確認できた事実: 既存実装は固定間隔で再接続し、接続成功直後に試行回数をリセットしていた。承認済み仕様書にはバックオフ、jitter、安定接続の定義がない。
- 未決定または矛盾: 基準間隔、最大待機時間、jitterの範囲、既定の最大試行回数、安定接続とみなす時間が未定義である。
- 実装への影響: 接続・切断を繰り返すノードに対する接続試行頻度と、利用者が観測する再接続停止条件が変わる。
- 仕様書作成者に求める決定: 再接続遅延、jitter、最大試行回数、試行回数をリセットする安定接続時間を仕様へ追加すること。
- 推奨案: 基準3秒、指数係数2、最大60秒、最大20%のjitter、既定10回、30秒安定後にリセットする。
- 暫定対応: 基準3秒、最大60秒、最大20%のjitter、既定10回、30秒安定後リセットを実装した。`reconnectInterval: 0`は受け付けない。
- 検証条件: 即時切断を連続させた場合に遅延が増加し、安定接続前は試行回数が維持され、安定接続後だけリセットされることを確認する。

## SEC-004: STOMP ERRORの重大度と終了動作

- 分類: SECURITY
- 該当箇所: `NemWebSocketError` のエラー分類（既存READMEのみ）
- 確認できた事実: `@stomp/stompjs` はサーバーのSTOMP `ERROR`フレームを`onStompError`へ通知する。既存実装はこのcallbackを設定していなかった。
- 未決定または矛盾: ERRORの種類ごとの重大度、自動再接続の可否、利用者へ渡すメッセージの内容が未定義である。
- 実装への影響: ERRORを通常切断として扱うと、認証・プロトコルエラーに対する再接続を繰り返す可能性がある。
- 仕様書作成者に求める決定: ERRORの分類、利用者通知、接続終了、自動再接続停止条件を仕様へ追加すること。
- 推奨案: ERRORはfatalとして通知し、同一接続の自動再接続を停止する。サーバーmessageは長さ制限を付けて通知する。
- 暫定対応: すべてのSTOMP `ERROR`を`connection`/`fatal`として通知し、messageを256文字に制限したうえで接続を破棄する。
- 検証条件: ERROR受信時に`onError`が一度呼ばれ、fatal情報が渡され、close後に再接続が予約されないことを確認する。
