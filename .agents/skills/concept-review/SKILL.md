# Concept Review Board

コンセプトを設計・実装・書き直すのではなく、要件定義を開始できる品質かを判定する。完璧さや Minor の解消を目的にレビューを継続してはならない。

## 対象と成果物

- レビュー対象は、ユーザーが明示したコンセプトシート1件とする。
- 明示されない場合は、`concept-sheet.md`、`concept.md`、ファイル名に `concept` を含む Markdown ファイルの順で候補を探す。`concept-review-findings.md`、要件定義書、設計書、実装コード、過去のレビュー結果は除外する。
- 候補が0件または複数件なら、推測で選ばず対象を確認して終了する。
- 成果物はリポジトリ直下の `.reviews/concept-review-findings.md` とし、レビューごとに上書きする。製作者へ公開するレビュー成果物はこのファイルだけとする。

## 実行順序

1. `reviewers.md` を読む。
2. `review-process.md` を読む。
3. `review-gates.md` を読む。
4. `output-format.md` を読む。
5. 定められた Phase 1 から Phase 3 を実施し、成果物を生成する。

討議、投票、Reviewer 個人の意見、却下理由、思考過程は内部情報であり、成果物へ含めない。

## 共通原則

- 「何を作るか」を確認し、「どう作るか」の設計・実装判断はしない。
- 指摘は対象箇所、根拠、影響、必要な修正を示せる場合だけ採用候補とする。
- コンセプト本文、ユーザー提供資料、`docs/knowledge` の確認済み資料を根拠の種別として区別する。未確認の事実、推測、好みを事実として扱わない。
- 技術的または安全性上の前提は、Reviewer C だけが必要時に `docs/knowledge` の関連資料を選んで参照して評価する。資料を確認できないことだけを不合格理由にしない。
