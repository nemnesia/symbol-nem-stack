# Review Gates

目的は、仕様書を完璧にすることではなく、実装を安全に開始できるかを判断することである。各ゲートは合格または不合格とし、不合格は必ず Critical の採用指摘に対応付ける。

## 品質ゲート

1. **目的と範囲**: 解決する課題、対象利用者、対象範囲、対象外を一意に理解できる。
2. **機能と制約**: 提供する機能、入力、出力、制約、および受け入れる結果を確認できる。
3. **処理と例外**: 正常時の処理、状態または順序、失敗条件、例外時の結果を確認できる。
4. **内部整合性**: 用語、要件、例、図表、関連資料の間に実装を妨げる矛盾がない。
5. **検証可能性**: 受け入れ条件、境界条件、失敗条件を基に、独立して検証できる。
6. **不可欠な前提の現実性と安全性**: 実装開始に不可欠な技術、運用、外部連携、法務、ライセンス、セキュリティ上の前提が未確認のまま残っておらず、確認済み資料と矛盾しない。

Gate 6 の技術的または安全性上の前提は、該当する場合に Reviewer C が承認済みの要件またはプロジェクト資料の関連箇所を選んで確認する。資料が存在しない、または範囲外で確認できないだけでは不合格にしない。前提が実装開始に不可欠で、確認が必要な理由と影響を示せる場合だけ不合格とする。

## 範囲外

コード構造、使用技術、ライブラリ、インフラ、UI、API の具体的な実装、データベース設計などの詳細は対象外とする。ただし、それらに依存する前提が上記ゲートを満たさない場合は、「採用する詳細」ではなく「確認または明確化が必要な前提」として扱う。

## 判定と終了

- すべてのゲートが合格: **実装へ進める**。
- 1つ以上のゲートが不合格: **仕様の修正を優先する**。
- Major と Minor だけでは差し戻さない。

品質ゲートを満たした時点でレビューを終了する。より良い表現、代替案、残存 Minor を理由に継続してはならない。
