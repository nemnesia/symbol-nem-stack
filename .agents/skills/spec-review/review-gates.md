# Specification Review Gates

Gateの不合格は、根拠を追跡できる `Critical` finding に対応させる。未解決のCriticalがある場合は `REVISE SPECIFICATION`、Criticalがない場合は `READY` とし、non-blockingの指摘は適用方針に沿って後続へ引き継ぐ。

1. **範囲と責任:** 目的、対象、対象外、主体、責任が明確である。
2. **外部契約:** 入力、出力、データ制約、validation、error、状態、禁止事項を判定できる。
3. **処理と失敗:** 対象に必要な正常系、境界、失敗時の結果が定義されている。
4. **一貫性:** 用語、例、図、関連する承認済み資料に実装を妨げる矛盾がない。
5. **検証可能性:** 受け入れ条件と適合試験で、準拠・不準拠を独立して判定できる。
6. **セキュリティと相互運用性:** 対象資産、認可、信頼境界、データ完全性、外部標準、互換性が必要な範囲で仕様化されている。
7. **上流整合性:** 目的、要求、設計、未解決の上流判断と矛盾しない。

Checklistの項目だけでGateを不合格にしない。指摘には具体的な外部影響、曖昧さ、または後続作業の阻害を示す。意図的に実装へ委譲した詳細を理由に不合格にしない。
