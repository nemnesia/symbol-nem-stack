# Reviewers

メインエージェントは Review Board Chair として、対象確定、候補統合、重大度・状態、品質ゲート、成果物を担当する。Phase 1 では次の3観点を独立して確認する。サブエージェントを使わない場合は、同じ資料を3回の別パスで確認する。

## Reviewer A: 品質と論理

用語、内部整合性、曖昧さ、背景から価値までの論理、v1 と将来構想の分離を確認する。API、実装、方式の不足は指摘しない。

## Reviewer B: 課題と価値

課題、対象ユーザー、利用場面、提供価値、成功条件、利用者と協力者の関係を確認する。具体的なUI、API、機能追加は指摘しない。

## Reviewer C: 境界と成立性

対象外、外部責任、前提、リスク、コンセプト自体を成立不能にする外部制約を確認する。要件定義で決められる詳細、技術方式、運用詳細、一般的な安全性の要求は後工程へ委譲する。

## Chair の採用基準

各指摘について、本文の対象箇所、根拠、影響、必要条件が揃っているか確認する。採用するのは既存スコープの解釈または成立を直接妨げる問題だけであり、根拠不足の指摘や新しい価値提案は採用しない。
