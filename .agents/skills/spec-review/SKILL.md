# Specification Review

実装者が推測せずに外部動作を実装・検証できる仕様かを判定する。承認済み要求、設計、適用される標準、関連仕様と照合する。製品の再設計、仕様書の編集、新しい要求の発明は行わない。

## 作業前の確認

1. 対象リポジトリの作業指示と `../review-common/review-playbook.md` を読む。
2. 対象に関係する reviewers、security checklist、review gates、output formatを読む。
3. 仕様書と直接関係する承認済み上流資料を特定する。対象が曖昧なら推測しない。
4. 互換性、実現可能性、外部技術の事実を確認する場合だけ、実装、SDK、テスト、fixture、公式資料を参照する。

## レビュー観点

- 適用範囲、用語、主体、責任、前提、トレーサビリティ
- 公開入力・出力、データ契約、必須性、制約、version
- validation、正規化、成功・失敗、error、状態変化、禁止事項
- 直列化、encoding、精度、認証、完全性、replay、互換性（該当する場合）
- 宣言された資産や承認済み要求に対応したセキュリティ・プライバシー契約
- 受け入れ条件や適合試験で準拠・不準拠を判定できるか
- 設計・実装へ委譲した詳細が適切な工程に残っているか

チェックリストは補助資料に限る。指摘は対象仕様と、承認済み上流資料、適用規則、または具体的な矛盾へ追跡する。上流設計の不足と仕様の欠陥を区別する。意図的に実装へ委譲された詳細の不足を欠陥にしない。

## Gateと結果

既存のレビュー保存先、命名、重大度、Gate、判定の規則に従う。各指摘には対象契約、曖昧さや矛盾、利用者または相互運用への影響、判定可能な契約にするための最小限の修正を記す。

仕様書は変更しない。確認した根拠、実施した確認、取得できなかった資料、未確認範囲、指摘、Gate結果、最終判定を報告する。レビュー記録に秘密情報や個人情報を含めない。
