# Output Format

Review Board Chair は、指定された出力先にレビュー結果ファイルだけを生成または更新する。Reviewer 個人の意見、討議、投票、反論、却下理由、思考過程は記載しない。

出力先の指定がない場合は、リポジトリルートの `.reviews/implemant-review.md` を使用する。同じ対象を再レビューする場合は同じファイルを更新し、古い判定や解消済み指摘を現在の結果と混同させない。

レビュー対象の実装、仕様書、fixture、テストは変更しない。

```markdown
# Implementation Review Findings

## Review Target

- 対象: <実装コード、テスト、差分、コミットまたは Pull Request のパスまたは識別子>
- 確認日: <YYYY-MM-DD HH:mm>
- レビュー範囲: <確認した範囲>
- 未確認範囲: <未確認事項。なければ「なし」>

## Evidence Used

| 種別 | 参照箇所 | 用途 |
| --- | --- | --- |
| 実装コードまたは差分 | <ファイル、行、コミットまたは PR の箇所> | <確認した実装> |
| テストまたは fixture | <ファイル、行または未確認> | <検証範囲の確認> |
| 承認済み仕様 | <パス、見出しまたは未確認> | <仕様適合性の確認> |
| 技術資料 | <資料の種別、パス、版または未確認> | <プロトコル、相互運用性または前提の確認> |

確認できない事実は「未確認」と記載し、推測を事実として記載しない。

## Review Result

<実装へ進める | 実装の修正を優先する>

## Summary

<改善案を含めない総合評価を3〜10行で記載する。現在の対象範囲に関係しない改善余地や将来拡張は含めない。>

## Required Changes

Critical と Major の採用指摘だけを記載する。該当しない場合は「なし」とする。

### IR-001

- Priority: <Critical | Major>
- 対象箇所: <ファイルと行、テスト、fixture または差分の箇所>
- 問題: <既存仕様または実装上の具体的な欠陥>
- 根拠: <種別と参照箇所>
- 発生条件: <再現条件>
- 影響: <現在の対象範囲で放置した場合の具体的影響>
- 修正内容: <欠陥を解消するための必要条件。新機能や具体的な解決方式を指定しない>
- 修正完了条件: <既存仕様を満たしたと判断できる最小十分な条件>
- 追加テスト: <必要な場合だけ記載>

## Optional Improvements

Minor の採用指摘だけを記載する。Minor は既存仕様または変更範囲内の実装・テストの明確性、保守性、検証可能性に関する具体的な小さな欠陥に限定する。将来拡張、追加機能、追加防御、汎用化、ベストプラクティスの提案は記載しない。該当しない場合は「なし」とする。

### IR-010

- Priority: Minor
- 対象箇所: <ファイルと行、テスト、fixture または差分の箇所>
- 改善内容: <現在の対象範囲に必要な小さな修正>
- 根拠: <種別と参照箇所>
- 影響: <現在の対象範囲で改善する理由>

## Specification Conformance

- 適合している要件: <要件と確認箇所>
- 不適合の要件: <要件と IR ID。なければ「なし」>
- 実装されていない要件: <要件と IR ID。なければ「なし」>
- 仕様が曖昧で判定できない要件: <要件と未決定事項。なければ「なし」>

## Test Evaluation

- 十分に検証されている範囲: <確認したテスト、fixture、適合テスト>
- 不足しているテスト: <既存仕様の検証に必要な不足。なければ「なし」>
- fixture または期待値の問題: <問題と IR ID。なければ「なし」>
- 実行されていない検証: <未実行のコマンドまたは環境。なければ「なし」>

## Review Gates

| Gate | 結果 | 根拠 |
| --- | --- | --- |
| 仕様適合性 | <合格 | 不合格> | <参照箇所または IR ID> |
| セキュリティ | <合格 | 不合格> | <参照箇所または IR ID> |
| 相互運用性とプロトコル | <合格 | 不合格> | <参照箇所または IR ID> |
| 処理と異常系 | <合格 | 不合格> | <参照箇所または IR ID> |
| テスト十分性 | <合格 | 不合格> | <参照箇所または IR ID> |
| 変更範囲内の品質 | <合格 | 不合格> | <参照箇所または IR ID> |

## Remaining Risks

修正後も残る可能性があるリスク、外部確認が必要な事項、仕様上の未決定事項を示す。新しい機能や追加対策の提案一覧にはしない。

## Final Decision

<Review Result と同じ判定を記載し、理由を2〜5行で記載する。>
```

指摘は、実装者がこのファイルだけで必要な修正または確認を実施できる粒度にする。ただし、問題の解消条件を超えて、特定の設計、アルゴリズム、ライブラリ、データ形式または追加機能を指定してはならない。
