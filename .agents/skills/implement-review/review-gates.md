# Review Gates

目的は、実装を完璧にすることではなく、承認済み仕様を現在の対象範囲で安全かつ検証可能に満たしているかを判断することである。各ゲートは合格または不合格とし、不合格は必ず Critical の採用指摘に対応付ける。

ゲートは新しい要求を発見するためのチェックリストではない。承認済み仕様と今回の変更範囲に対してのみ適用し、将来拡張や一般的ベストプラクティスを満たすためにスコープを広げてはならない。

## 品質ゲート

1. **仕様適合性**: 承認済み仕様の入力、出力、制約、処理、状態、エラーおよび禁止事項を、実装が対象範囲で満たしている。
2. **セキュリティ**: 仕様が扱う資産、権限、秘密情報および信頼境界に対して、要求された保護と失敗時の安全性を実装が満たしている。
3. **相互運用性とプロトコル**: 仕様が要求するエンコード、署名対象、数値表現、チェーン、ネットワークおよび外部形式が、別実装でも同じ結果になる。
4. **処理と異常系**: 対象範囲の正常系、異常系、境界値、入力検証、エラー分類および状態遷移を実装が仕様どおりに扱う。
5. **テスト十分性**: 既存のテスト、fixture および検証結果が、対象範囲の重要な仕様違反、退行、非互換および失敗を独立して検出できる。対象実装の行・分岐・関数カバレッジは90%以上を目標とし、未達の場合は未カバー範囲と理由を確認する。
6. **変更範囲内の品質**: 変更範囲内の構造、型、依存、例外処理およびコメントが、具体的な欠陥や仕様違反を生じさせていない。好みだけのリファクタリングは要求しない。

## 範囲外

次の事項は、承認済み仕様または今回の変更範囲に具体的な根拠がない限り範囲外とする。

- 仕様にない機能、公開 API、設定、フィールド、エラー、フォールバック、互換性
- 将来拡張のためだけの予約領域、抽象化、プラグイン化、設定可能化
- 未要求の運用機能、監査機能、管理機能、監視、バックアップ、ローテーション
- 想定スコープ外の利用者、環境、チェーン、ネットワークまたは攻撃モデルへの対応
- 一般的なベストプラクティスだけを根拠とする追加防御、追加認証、追加上限、追加テスト
- 内部実装方式の好み、変更と無関係なリファクタリング、将来の保守性だけを理由とする修正

仕様自体が未決定で実装の正否を判断できない場合は、実装欠陥と仕様欠落を分離する。仕様欠落だけを理由にコードの不合格判定を行ってはならない。

## 判定と終了

- すべてのゲートが合格: **公開可能**。
- 1つ以上のゲートが不合格: **修正後に再レビュー**。
- Major と Minor だけではゲートを不合格にしない。ただし、Required Changes または Optional Improvements に採用した指摘として記録する。

カバレッジ90%未満だけを理由にゲートを不合格としてはならない。仕様上重要なケースの未検証、または未カバー範囲に具体的な欠陥・退行リスクがある場合に、その根拠とともに判定する。

品質ゲートを満たした時点でレビューを終了する。より良い実装方式、代替案、残存 Minor、将来の改善余地を理由にレビューを継続してはならない。
