# Symbol Sign-On v1 適合試験仕様

## 文書情報

| 項目 | 内容 |
| --- | --- |
| 文書種別 | 適合試験仕様書 |
| 対象 | Symbol Sign-On v1の仕様適合性・相互運用性確認 |
| 対象チェーン | Symbol |
| 対象ネットワーク | 初期検証: Testnet、正式提供: Mainnet |
| 参照仕様 | [spec-authentication.md](./spec-authentication.md)、[spec-public-state.md](./spec-public-state.md)、[spec-sso-integration.md](./spec-sso-integration.md)、[spec-revocation-operations.md](./spec-revocation-operations.md) |
| 状態 | 初版 |

本書は、4つの機能仕様に定義された外部動作を検証する。fixtureの具体値が未決定の項目は、試験シナリオと期待結果までを定義し、推測した署名バイト列・Protocol版・鍵・Metadata値をfixtureとして作成しない。

## 1. 適合試験の原則

- 試験対象のチェーン、ネットワーク、Protocol版、署名クライアントおよび参照先を記録する。
- Testnetの結果をMainnetの適合性へ自動的に読み替えない。
- 署名対象バイト列が未確定の間は、署名検証のfixtureを正式な相互運用ベクトルとして扱わない。
- 秘密鍵、ニーモニック、パスワードおよびそれらを復元できる値を、fixture、ログ、例外または試験記録へ平文で含めない。
- 試験結果は、仕様上の期待結果、実際の結果、使用環境および未確認事項を区別して記録する。

## 2. 共通試験データ

試験データは、少なくとも次の論理情報を識別できるものとする。

| 情報 | 目的 |
| --- | --- |
| 対象ネットワーク | Testnet/Mainnet混同の検出 |
| 対象サービス | サービス間の結果混同の検出 |
| 認証主体識別子 | 主体継続性と識別子検証の確認 |
| Main/Child関係 | 強化認証と失効の確認 |
| 認証要求状態 | 未発行、期限切れ、使用済み等の確認 |
| 公開状態 | 未受入れ、反映待ち、確認済み、信頼不能、参照不能の確認 |
| 期待結果 | 成立、拒否、失効、停止または待機の別 |

具体的なアドレス、Namespace、Metadataキー、署名、時刻およびトランザクションは、対象Protocol版と承認済み形式が確定した後に生成する。

## 3. 認証試験

| ID | 試験条件 | 期待結果 |
| --- | --- | --- |
| AUTH-001 | 有効な単一認証鍵で、対象サービス・対象ネットワークに対応する未使用要求へ署名する。 | 通常認証が成立する。 |
| AUTH-002 | 署名対象を改変する。 | `SIGNATURE_INVALID`または同等の拒否となる。 |
| AUTH-003 | 未発行の要求に対応する署名を提示する。 | 認証を成立させない。 |
| AUTH-004 | 期限切れの要求に対応する署名を提示する。 | `REQUEST_EXPIRED`または同等の拒否となる。 |
| AUTH-005 | 使用済み要求または署名を再提示する。 | `REQUEST_REUSED`または同等の拒否となる。 |
| AUTH-006 | 別サービスを対象とする要求の署名を提示する。 | `SERVICE_MISMATCH`または同等の拒否となる。 |
| AUTH-007 | Testnet対象の署名をMainnet対象として提示する。 | `NETWORK_MISMATCH`または同等の拒否となる。 |
| AUTH-008 | 認証主体識別子をアドレスで指定する。 | 対象ネットワークを含めて一意に比較できる。 |
| AUTH-009 | 認証主体識別子をNamespaceで指定し、信頼できるアドレスへ解決する。 | 解決結果を対象ネットワークとともに認証判断へ使用できる。 |
| AUTH-010 | Namespaceの解決不能、ネットワーク不一致または参照時点不明を発生させる。 | 確認不能な解決結果で認証を成立させない。 |
| AUTH-011 | 強化認証を設定していない利用者が通常認証する。 | 通常認証が成立する。 |
| AUTH-012 | Child署名、Main側承認およびChild制御確認が確認済みである。 | 強化認証が成立する。 |
| AUTH-013 | Child側参照だけを提示し、Main側承認を欠落させる。 | 強化認証を成立させない。 |

## 4. 公開状態試験

| ID | 試験条件 | 期待結果 |
| --- | --- | --- |
| STATE-001 | 変更がノードに受け入れられていない。 | 変更後状態を認証根拠にせず、再送可能な状態として扱う。 |
| STATE-002 | 変更が受け入れられたがチェーン反映を確認できない。 | 変更後状態を認証根拠にせず、待機状態として扱う。 |
| STATE-003 | 変更がチェーン上に反映され、信頼性を確認できる。 | `CONFIRMED`として強化認証へ使用できる。 |
| STATE-004 | 最新性、完全性または出所を確認できない。 | `UNTRUSTED`として新規強化認証を拒否し、依存状態を失効させる。 |
| STATE-005 | 公開状態を取得または確認できない。 | `UNAVAILABLE`として新規強化認証を拒否し、依存状態を失効させる。 |
| STATE-006 | 変更後状態が未確認の間に、直前の確認済み状態を参照する。 | 変更の存在だけで直前状態を信頼不能にしない。 |
| STATE-007 | Testnetの公開状態をMainnetの認証へ使用する。 | ネットワーク不一致として拒否する。 |

## 5. 失効・障害試験

| ID | 試験条件 | 期待結果 |
| --- | --- | --- |
| REV-001 | 旧Childから新Childへ変更し、新Childの関係が確認済みになる。 | 旧Childを拒否し、新Childを同一認証主体として扱い、旧依存状態を失効させる。 |
| REV-002 | Childを失効し、新Childがまだ存在しない。 | 強化認証を拒否し、通常認証を維持する。 |
| REV-003 | Main/Child公開状態が信頼不能になる。 | 依存する強化認証状態を期限待ちにせず失効させる。通常認証は継続可能とする。 |
| REV-004 | 単一参照先が利用不能で別参照先から確認できる。 | 直ちに強化認証を停止しない。 |
| REV-005 | すべての参照先で信頼できる状態を確認できない。 | 強化認証を安全側に停止し、依存状態を失効させる。 |
| REV-006 | 認証基盤が認証の正当性を保証できない。 | 新規認証を停止し、影響する状態を失効対象にする。 |
| REV-007 | 対応サービスが失効結果を受信する。 | サービス固有の認証状態またはセッションを継続利用させない。 |
| REV-008 | 失効結果を確認できない状態を成功として扱う。 | その扱いを拒否する。 |

## 6. SSO連携試験

| ID | 試験条件 | 期待結果 |
| --- | --- | --- |
| SSO-001 | 提供許可されたサービスを対象に認証する。 | 当該サービスだけが有効な結果を受け取る。 |
| SSO-002 | 未許可または停止済みサービスを対象に認証する。 | 新たな認証結果を提供しない。 |
| SSO-003 | サービスAの認証結果をサービスBへ提示する。 | サービス対象不一致として受け入れない。 |
| SSO-004 | 認証成功結果をサービス固有の権限付与として扱う。 | 認証契約上、その意味付けを許可しない。 |
| SSO-005 | あるサービスの提供許可を停止する。 | 他サービスの許可状態を暗黙に変更しない。 |
| SSO-006 | 認証関連通信を平文HTTPで行う。 | `SECURE_TRANSPORT_REQUIRED`として拒否する。 |
| SSO-007 | 未対応の契約版を受け取る。 | `CONTRACT_UNSUPPORTED`として拒否する。 |

## 7. 責任境界・秘密情報試験

| ID | 試験条件 | 期待結果 |
| --- | --- | --- |
| SEC-001 | 認証処理のログ、例外、デバッグ出力および試験記録を確認する。 | 秘密鍵等の秘密情報を平文で含まない。 |
| SEC-002 | 認証基盤と対応サービスの入力・保存情報を確認する。 | 秘密鍵を取得・保存しない。 |
| SEC-003 | 署名クライアントが利用不能になる。 | SSO全体の障害と誤認せず、署名クライアント側の責任境界を示す。 |
| SEC-004 | Main喪失または鍵紛失を発生させる。 | v1が秘密鍵復元・Main復旧を提供しないことを確認できる。 |

## 8. 未決定事項と試験の保留

次の項目が確定するまで、該当試験は正式な相互運用試験として完了扱いにしない。

- 署名対象の正確なバイト列、文字コードおよびシリアライズ方式
- 対象Protocol、ノード、REST GatewayおよびSafelySignSymbolの対応版
- Main/Child Metadataのキー、値、更新方式および確認閾値
- Namespace解決の継続条件
- SSOの採用プロトコル、認証結果、Token、セッションおよび失効方式
- 参照先切替と公開状態の最終性判定
