## 1. 失効対象

認証基盤は、次の認証状態を区別して扱う。

| 論理状態 | 依存情報 |
| --- | --- |
| 通常認証状態 | 通常認証鍵、認証要求および署名結果 |
| 強化認証状態 | Child署名、Main/Child関係および確認済み公開状態 |
| サービス提供状態 | 対応サービスへの認証結果提供許可 |
| 認証基盤状態 | 認証の正当性を提供できる状態 |

失効は、対象を区別して適用する。強化認証の公開状態だけが失効または参照不能になった場合、通常認証状態を同じ理由で失効させてはならない。

## 2. Child変更・失効

### 2.1 Child変更

新ChildのMain側承認とChild制御確認が `CONFIRMED` になるまで、新Childを強化認証に使用してはならない。新Childが有効になった後は、旧Childによる強化認証を拒否し、旧Childに依存する認証状態を通常の有効期限を待たずに失効させる。

認証主体識別子は維持する。対応サービス固有のアカウント、プロフィール、権限、セッションまたはデータ継続性は本仕様の保証対象外である。

### 2.2 Child失効

- 失効が `CONFIRMED` になった旧Childによる強化認証を成立させない。
- 新Childが確認されるまで強化認証を成立させない。
- 旧Childに依存する認証状態を直ちに失効対象とする。
- Mainによる通常認証は継続可能とする。
- 秘密鍵を復元せず、失効・変更で同一認証主体を維持する。

### 2.3 Main喪失

Mainアカウントの紛失、漏洩、交換または別Mainへの移行から認証主体を継続することはv1で保証しない。Symbol Sign-Onは秘密鍵の復元、利用者に代わる鍵管理、バックアップまたは復旧代行を提供しない。

## 3. 公開状態の信頼喪失

公開状態が `UNTRUSTED` または `UNAVAILABLE` になった場合、次の動作を行う。

- その公開状態を根拠とする新規強化認証を成立させない。
- その公開状態に依存する既存認証状態を、通常の期限を待たず失効させる。
- 失効結果を、対象サービスが認識できる形式で提供する。
- 通常認証は、当該公開状態の問題だけを理由に停止しない。

公開状態が再び取得可能になったことだけで、失効済みの認証状態を自動的に復元してはならない。再認証の必要性と再開条件は未決定である。

## 4. 参照先障害

1. 単一の公開状態参照先が利用不能になった場合、直ちに強化認証を停止してはならない。
2. 認証基盤運用主体は、利用可能な別の参照先から必要な公開状態を確認できるか判定する。
3. 切替後も信頼できる状態を確認できない場合、強化認証を安全側に停止し、依存認証状態を失効させる。
4. 認証基盤自体が利用不能な場合、新規認証を提供できない状態として扱う。
5. 認証の正当性を確認できる状態へ復旧した後に、認証提供を再開する。

参照先の選択、監視、切替、復旧判定、参照先間の一致確認および数値SLAは未決定である。

## 5. 認証基盤の障害・侵害

- 認証基盤の障害・侵害によって認証の正当性を保証できない場合、認証基盤運用主体は新規認証を停止できなければならない。
- 影響を受ける認証状態を失効対象として扱い、対応サービスが失効を認識できるようにする。
- 対応サービスは、失効を認識したサービス固有の認証状態またはセッションを継続利用させない。
- 障害または侵害の責任を、認証基盤運用主体、対応サービスおよび利用者に分けて扱う。
- 認証基盤自体へ接続できない場合の利用者向け案内はv1の必須機能としない。
- 認証基盤へ接続可能な場合、利用者が認証不成立と障害を区別できる案内を提供する。

## 6. 失効結果のサービス反映

認証基盤は、少なくとも次の論理情報をサービスへ提供できなければならない。

| 情報 | 意味 |
| --- | --- |
| 対象サービス | 失効結果を適用するサービス |
| 対象認証主体 | 失効した認証主体または認証状態 |
| 失効対象 | 通常認証、強化認証、特定Childまたは公開状態 |
| 失効理由分類 | Child失効、公開状態信頼喪失、参照不能、基盤障害・侵害など |
| 有効時点 | 失効を認証判断へ適用する時点 |
| 契約版・ネットワーク | 結果の解釈環境 |

提供方式、Push/Polling/Introspection、反映遅延、サービス側の強制ログアウト方式は未決定である。対応サービスは、失効結果を受け取れないことを成功として扱ってはならない。

## 7. データ保持と管理操作

- 認証要求、署名結果、認証結果、公開状態および運用・調査記録は、目的達成に必要な情報だけを必要な期間保持する。
- 一時情報は目的達成後に継続保持しない。
- 認証履歴の長期保存を通常機能として必須にしない。
- 運用・調査記録を保持する場合、目的を限定し、目的外に利用せず、削除可能とする。
- サービス参加・停止、認証状態失効、緊急停止その他の重要な管理操作は、操作主体と対象を事後に確認できる状態にする。
- 秘密鍵、ニーモニック、パスワードその他の秘密情報をログ、例外、デバッグ出力または監査記録へ平文で含めてはならない。

具体的な保持期間、削除方式、管理権限、承認手順、記録項目および記録形式は未決定である。

## 8. 状態とエラー

| 分類 | 認証基盤の扱い |
| --- | --- |
| `REVOCATION_CONFIRMED` | 対象認証状態を失効扱いにする |
| `REVOCATION_PENDING` | 失効反映前として新規強化認証の扱いを公開状態仕様に従わせる |
| `PUBLIC_STATE_UNTRUSTED` | 新規強化認証を拒否し、依存状態を失効させる |
| `PUBLIC_STATE_UNAVAILABLE` | 新規強化認証を拒否し、依存状態を失効させる |
| `REFERENCE_FAILOVER_REQUIRED` | 別参照先での確認を試みる |
| `AUTHORITY_UNAVAILABLE` | 新規認証を提供しない |
| `AUTHORITY_COMPROMISED` | 影響範囲を停止・失効対象として扱う |
| `SERVICE_RESULT_NOT_CONFIRMED` | サービスはログイン成功として扱わない |
